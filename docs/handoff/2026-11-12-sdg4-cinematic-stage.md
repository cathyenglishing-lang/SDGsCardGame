## 2. 電影感舞台

| 部分 | 檔案 | 內容 |
|---|---|---|

| 後處理 | `js/world/post.js` | 泛光、景深（對焦講者）、調色（S 曲線、冷暗部暖亮部、暗角、顆粒）。四個等級：3 全開、2 半解析度泛光、1 不做後處理改用 CSS 暗角、0 再降解析度並關粒子。前 2.5 秒暖機後每 3 秒量一次幀率，低於 28 fps 就降一級，**只降不升**，避免畫面閃來閃去。`?q=high` 或 `?q=low` 會固定等級。 |

## 3. 數據鏈

舞台送出的事件（都進 `learning_events`，沒有新資料表；舊版的局照樣讀得出來，只是少了時間類欄位）：

| 事件 | 內容 |
|---|---|
| `run.start` | 載入毫秒、選等級畫面停留、畫質等級、是否手機、視窗大小、語音辨識有沒有 |
| `phase` | 階段切換：intro → pier → walk → backstage → present → ending，附上一階段毫秒數 |
| `pk.part` / `pk.part.read` | 段落說明卡出現與讀了多久 |
| `pk.slide.start` | 一張投影片的一次嘗試開始。中途離開的人，也能知道停在第幾張 |
| `pk.slide` | 一張結束：停留毫秒、念了幾次、重講、聽到比例、對與錯的字數、說出的字數、辨識引擎、沒念對的字 |
| `pk.redo` / `pk.model` | 這張重來 / 聽示範 |
| `page.hide` / `page.show` | 離開或回到分頁（手機鎖屏、切 App）。離開時立刻送出佇列 |
| `ending` | 各階段總時間 |

由事件算出的指標（`backend/sdg4_reports.py`）包括：逐張走到與念完的次數和完成率、停留秒數中位數、重講比例、聽示範比例、平均聽到比例、念對率、最常沒念對的字、各階段耗時中位數、中途離開點（第幾張途中或念完後、說明卡、哪個階段，以及是否離開分頁）、念對率分布，以及裝置與載入秒數。

## 4. 籌碼

- **念對的字：** 每 10% 一枚，最多 10 枚。數字由伺服器從事件裡的對與錯字數算出（`learning.sdg4_score`），不信瀏覽器自己報的。
- **正式模式念完：** 另加 5 枚。
- **成績在最後一張念完時就送出**，不等林老師的結語。學生在掌聲中關掉頁面，也算完成，照樣有籌碼和報告。伺服器端另外把「20 張都念完」也當成完成。
- **至少念 18 張才有籌碼。** 默讀（沒有語音辨識）只拿正式的 5 枚。
- **每帳號每天最多 3 場有籌碼**（`classroom.SDG4_PAID_RUNS_PER_DAY = 3`）。次數從籌碼帳本算，老師作廢的那一場會讓出名額。**這是我的解讀：** 你說「不要刷超過三次」，我做成每天三次。要改成終身三次，只需把條件改成不看日期，一行的事。
- **太快的局先扣住：** 整場不到 280 秒，籌碼要等老師在「課程與名單 › 籌碼」確認才入帳。用 `?fast=1` 測試的局也會被扣住。
- **不給籌碼：** 老師、管理員、測試帳號、沒登入的人。
- **規則版本：** `CHIP_RULE_VERSION` 升為 2。已經入帳的籌碼不重算。

## 5. 老師的 SDG 4 頁（遊戲數據 › SDG 4 Stage）

- **全班：** 六個總數字，接著是「這個遊戲裡要查看的學生」和「先看這幾位」。另有六張圖：逐張走到與念完、逐張聽到比例、逐張停留、階段耗時、中途離開點、念對率分布，每張圖下面附一句白話結論。再來是學生表和最近的上台。可依課程、系級、等級、練習或正式、日期篩選。
- **學生：** 狀態、代表的一次、異常原因、每次念對率、常錯字、逐張「最近一次 vs 最好一次」、每次上台。
- **單次：** 一句總結、六個數字、異常、階段時間條、每張投影片的表格，以及全部操作紀錄。
- **Excel：** 含姓名版和研究用版。工作表有 README、Summary、Students（含狀態、代表一次、異常）、Runs、Slides、RunSlides、Phases、Exits、MissedWords、Anomalies、Events。

### 異常怎麼判斷（照你說的：以每一次上台為單位，再彙整）

| 代碼 | 類型 | 條件 |
|---|---|---|
| `too_fast` | 好得不合理 | 整場不到 280 秒 |
| `few_slides` | 好得不合理 | 念不到 18 張就送出完成 |
| `more_right_than_said` | 好得不合理 | 念對的字比說出口的字還多，很可能不是從遊戲畫面送出 |
| `short_slides` | 好得不合理 | 每張停留中位數不到該張秒數的六成 |
| `no_voice` | 值得一起看 | 麥克風開著，但六成以上的投影片幾乎沒聲音 |
| `left_tab` | 值得一起看 | 一場離開分頁 3 次以上 |

學生層級再加兩條：兩場之間念對率跳 40 個百分點以上，以及上一場沒結束就開新的一場。

**跨遊戲：** `GET /learning/records/watchlist` 把卡牌遊戲和 SDG 4 的異常學生合成一張名單，被兩個遊戲都標記的排最前面。SDG 4 頁的異常名單會標「Card Game 也被標記」。3D 港口遊戲還沒納入。

### 放棄過又完成的學生

| 狀態 | 意思 |
|---|---|
| `steady` | 每次都念完 |
| `recovered` | 放棄過，後來念完。標成「放棄後又完成（不穩定，不是學習不佳）」，**不列進「先看這幾位」** |
| `unstable` | 完成過，但最近一次又中途離開 |
| `abandoned_only` | 從來沒念完。會列進「先看這幾位」，建議老師直接聊 |

「代表的一次」取念完的上台裡念對率最高、而且沒有「好得不合理」異常的那一次。放棄過的場次不會拉低它，這就是平台上這位學生的最佳狀態。

### 學習報告：一場一份

- **在全班頁勾選上台再發出**（可以附一段話給學生）。單次頁也有「把這一次的報告發給學生」。
- **中途離開的上台不能勾，也不會發。** 發出後畫面會列出「哪幾位是中途離開、停在第幾張，所以沒有發」。最近狀態是放棄的學生，會自動附進這份提醒。
- **同一場不重複發**，除非勾「再發一次」。報告表會顯示「報告已發」或「報告已讀」。
- **學生端：** 在原本的「我的學習報告」收到。內容有念對率、念完幾張、重講、老師的話、下次先練的字、逐張聽到比例。

API：`POST /teacher/reports/sdg4-run`、`GET /teacher/reports/sdg4-sent`。

## 7. 資安：路徑穿越與真實路徑

照你的要求，網址不能被拿來指到伺服器上的任意檔案，任何回應也不能透露部署環境的真實路徑。

| 做了什麼 | 在哪裡 |
|---|---|
| 所有請求先過一道路徑檢查。含 `..`、反斜線、NUL 或控制字元、以 `.` 開頭的路徑段（`.git`、`.env`），以及原始碼或筆記類副檔名（`.md`、`.py`、`.map`、`.bak`、`.sql`、`.db`、`.log`…）都回 404。`%252e%252e` 這類多重編碼會先完全解碼再檢查。回應和找不到檔案時一模一樣，不透露磁碟上有什麼。所有回應加上 `X-Content-Type-Options: nosniff`。 | `backend/main.py` `path_guard` |
| `/pages/{名稱}`：名稱只接受小寫英數、`-`、`_` 加 `.html`。解析後的檔案必須直接在 pages 資料夾裡。原本在 Windows 上，用反斜線的 `..\x.html` 可以讀到資料夾外的 HTML。 | `backend/main.py` `frontend_page` |
